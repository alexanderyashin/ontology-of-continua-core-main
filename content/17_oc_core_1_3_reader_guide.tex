\section{Reader Contract and Navigation Guide}
\label{sec:oc13-reader-contract}

Core~1.3 is the flagship reader-facing monograph, but readers arrive with
different tasks. This guide is therefore a route map rather than a second introduction.
Its job is to show where readers following the five recommended routes should begin:
Reviewer route, Formal reader route, Domain reader route, Broad scientific reader route, and Practical user route. External
collaborators who need deployment guidance should use the Practical user
route.

The dedicated Figure Atlas in
Appendix~\ref{sec:oc-core-1-3-figure-atlas} and the Technical Derivation Atlas
in Appendix~\ref{sec:oc-core-1-3-technical-derivation-atlas} are intentionally
outside the default continuous reading route. Their material belongs to the
appendix inspection layer; the formal-reader route below consults the
Technical Derivation Atlas only when local proof support is needed.

\subsection{The five reading routes}

The reviewer-navigation appendix uses slightly narrower review labels:
``rapid critical reviewer'' corresponds to the Reviewer route, ``formal
mathematical reviewer'' to the Formal reader route, and ``generalist
scientific reviewer'' to the Broad scientific reader route.

\textbf{Reviewer route.}
Read the front matter, this guide,
Sections~\ref{sec:results},
\ref{sec:oc13-publication-boundary}--\ref{sec:oc13-theorem-roadmap},
Section~\ref{sec:oc13-worked-examples},
and then
Appendices~\ref{sec:oc13-source-audit-appendix}--\ref{sec:oc13-reviewer-navigation}. That route exposes the publication boundary, theorem status,
load-bearing theorem spine, reviewer objections, and source witnesses as quickly
as possible.

\textbf{Formal reader route.}
Use Sections~\ref{sec:intro}--\ref{sec:conclusion} for orientation only.
Then read Sections~\ref{sec:boundary-extended}--\ref{sec:falsifiability-extended},
Section~\ref{sec:modules_master}, and
Sections~\ref{sec:oc13-publication-boundary}--\ref{sec:oc-core-1-3-unified-synthesis}
in order. Use Appendices~\ref{app:notation}--\ref{app:klevels-tables},
Appendix~\ref{sec:oc13-proof-machinery-appendix}, and the Technical
Derivation Atlas in Appendix~\ref{sec:oc-core-1-3-technical-derivation-atlas}
when local proof support is needed. This is the compact route that keeps
exact doctrine, theorem scope, and proof machinery visible at once.

\textbf{Domain reader route.}
Read Section~\ref{sec:disciplines-extended} and
Sections~\ref{sec:oc13-worked-examples}--\ref{sec:oc-core-1-3-practical-utility},
then move into
Appendices~\ref{sec:oc-core-1-3-empirical-validation-matrix},
\ref{sec:oc-core-1-3-domain-benchmark-manifest},
\ref{sec:oc-core-1-3-domain-benchmark-caseset},
\ref{sec:oc-core-1-3-domain-replay-reports},
\ref{sec:oc-core-1-3-domain-execution-board}, and
\ref{sec:oc-core-1-3-practical-utility-atlas}, with
Appendix~\ref{sec:oc-core-1-3-reference-benchmark-atlas} added only when
experiments, predictions, or falsifiability catalogues need inspection.
That path exposes bounded domain embedding, worked interpretation, empirical
promotion rules, replay surfaces, benchmark cases, execution board, practical
use, and comparison evidence without forcing the reader to traverse every
technical-derivation section first.

\textbf{Broad scientific reader route.}
Read Sections~\ref{sec:intro}--\ref{sec:conclusion},
Sections~\ref{sec:boundary-extended}--\ref{sec:falsifiability-extended},
Section~\ref{sec:modules_master}, and
Sections~\ref{sec:oc13-publication-boundary}--\ref{sec:oc-core-1-3-practical-utility}
straight through as a continuous graduate-level monograph. Use
Appendix~\ref{app:notation} for
notation when needed and defer Appendices~\ref{sec:oc-core-1-3-figure-atlas}--\ref{sec:oc-core-1-3-practical-utility-atlas} until a concrete figure,
benchmark table, or support dossier question arises. This is the recommended
route for a broad scientific reader.

\textbf{Practical user route.}
Read the front matter, this guide,
Section~\ref{sec:oc13-publication-boundary},
Section~\ref{sec:oc-core-1-3-practical-utility}, and
Appendices~\ref{sec:oc13-source-audit-appendix},
\ref{sec:oc13-journal-core-bridge}, and
\ref{sec:oc-core-1-3-practical-utility-atlas} first; add
Appendix~\ref{sec:oc-core-1-3-reference-benchmark-atlas} only when the task
requires experiments, predictions, or falsifiability catalogues. Return
to Sections~\ref{sec:oc-core-1-3-operationalization-program}--\ref{sec:oc-core-1-3-unified-synthesis}
only when a practical use case needs theorem, replay, or falsifier support to
be inspected in detail. This route is for external collaborators who need
deployment guidance: what can be predicted, which decisions can be supported,
which procedures can be run, and how the result compares with alternatives.

\subsection{Route legend}

The five routes above are the working navigation system:
\begin{itemize}[leftmargin=1.6em,nosep]
\item \textbf{Reviewer route}: shortest path to claim boundary, proof spine,
      objections, and source witnesses.
\item \textbf{Formal reader route}: compact path through doctrine, theorem
      scope, notation, and proof machinery.
\item \textbf{Domain reader route}: bounded path from domain embedding to
      replay, benchmarks, execution, use, and comparison evidence.
\item \textbf{Broad scientific reader route}: continuous graduate-level reading path
      through the main argument before atlas inspection.
\item \textbf{Practical user route}: shortest path to usable tasks, required
      inputs, outputs, comparison boundaries, and deployment constraints.
\end{itemize}

\subsection{What this guide is not}

This guide does not restate the theory, replace the theorem roadmap, or turn
the flagship monograph into a status summary. It simply tells the reader where each
task belongs. Section~\ref{sec:oc13-theorem-roadmap} covers proof navigation.
Section~\ref{sec:oc-core-1-3-unified-synthesis} covers the unified synthesis.
Section~\ref{sec:oc-core-1-3-practical-utility} covers practical consequences
and comparative analysis. The appendices keep the inspection burden inside the
same volume without displacing the main reading spine.
